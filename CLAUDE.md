# Knight Night — заметки для работы над проектом

Маленькая пиксельная игра про рыцаря: короткое приключение на 4–5 локаций (30–60 минут), главная механика — парирование ударов по высоте. Владелец — креативный директор проекта, сам не программирует. Общение на русском, прямо, без воды. Работа идёт короткими сессиями по вечерам, цель — к Новому году 2027.

Дизайн игры и принятые решения — в `docs/design.md`. Перед изменением механики свериться с ним и обновить его, если владелец что-то поменял.

## Стек и команды

Vanilla JS (ES-модули), Canvas 2D, без сборки и зависимостей. Звук синтезируется WebAudio.

```bash
npm test     # node --test: правила боя и поведение врага (src/combat.js, src/enemy.js)
npm start    # python3 -m http.server 8080 → http://localhost:8080
```

Модули нельзя открыть через `file://` — нужен локальный сервер.

Проверка в браузере: Playwright + Chromium уже стоят в облачной среде (`NODE_PATH=$(npm root -g) node script.js`). Состояние игры доступно как `window.knightNight` — по нему бот может проходить бои.

## Структура

- `src/config.js` — **все числа баланса**: окно парирования, урон, `WEAPON` (меч: удары и перемещения рыцаря), `RAPIER`, `ENEMY_TYPES`, `NPC_TYPES`, `ITEMS`, мир из комнат `ROOMS` (двери, края, встречи, декорации) и `START`, `VERSION`. Правки баланса — сюда. При заметном изменении поднимать `VERSION`.
- `src/combat.js` — чистые правила: исход удара врага или стрелы (dodged / warded / perfect / block / hit + множитель урона), зона попадания по слизню.
- `src/enemy.js` — враги: `createEnemy(type, x)`. Классы Melee (dormant → approach → idle → windup → strike → recover | stagger), Archer (держит дистанцию, hop, стрелы), Slime (hop, crouch → leap, retreat → inflate → suck). Враги закрываются от ударов рыцаря (`notifyAttack`, `guardChance`), удар во время их замаха — размен.
- `src/player.js` — рыцарь: ready / attack (windup → active → recover) / dash / backdash / roll / hurt / swallowed. `chooseAttack` выбирает удар по вводу, ножны, отмена замаха, буфер ввода.
- `src/poses.js` — позы (кисть, угол клинка, наклон, присед). Замах должен читаться по силуэту.
- `src/draw.js` — пиксельные примитивы и фигура бойца-заглушки.
- Анимации приёмов (v0.70): `tools/pixellab_anim.py <набор> <анимация>` (PixelLab от кадра набора) → `tools/add_anim.py` (в лист, кадры `<ключ>_N`); в игре — `anim` у `drawSprite`. Рост набора — `tools/resize_set.py`. Лестница в профиль — `STAIR_PATH`/`stairsGeom` в `src/background.js`.
- Надёжность кадра (v0.71): логика, рисование и свет в `frame()` (`src/main.js`) — в отдельных `try`, после ошибки холст сбрасывается (`resetCtx`); циклы с шагом от данных (картинка, `facing`, координаты) — всегда с пределом: бесконечный цикл вешает вкладку намертво. Двери открываются створкой из картинки закрытой двери (`DOOR_LEAF`). NPC уходят рывком в тень (`VANISH` в `src/enemy.js`).
- `src/fire.js` — живой огонь (v0.68): клеточная симуляция пламени, `getFire(key, opts)` + `drawFire`; камин, костёр, факелы.
- Оружие в руках — картинки `assets/objects/wpn_*.png` из `tools/draw_weapons.py` (рисуются попиксельно, не PixelLab); `WEAPON_IMG` в `src/sprites.js`. Лук — кодом.
- `src/sprites.js` — спрайты персонажей (v0.60 Найт, v0.64 враги): набор `assets/sprites/<имя>/` (+ `<имя>.json`: точка кисти каждого кадра, анимации), ближайшая поза из `src/poses.js`, оружие рисуется кодом от кисти (`drawWeapon`). Враг рисуется спрайтом, если его тип есть в `ENEMY_SPRITES`, иначе — старой фигуркой. Новый набор: `tools/pixellab_character.py <тип> "<описание>"` (≈120–150 генераций). Холст 640×360, мир — 320×180, масштаб `S = 2` в `src/main.js`.
- Плавность персонажей (v0.67): `tools/pixellab_smooth.py <набор> "<описание>"` добавляет набору разворот (turn_0…7), шаги вглубь (walkS/walkN), промежуточные позы (tw_…) и нормали; в игре враг разворачивается кадрами поворота (`turnFx`) и шагает вглубь видом спереди/со спины.
- Лавка (v0.67): экран торговли — `#shop-scene` (сцена `assets/shop/scene.png` + Лика по пояс `assets/shop/lika_<настроение>.png`, рисует `drawShopScene` в `src/main.js`), картинки — `tools/pixellab_shop.py`. Лика в комнате сидит на бочке (`sitImgs` в `NPC_TYPES`).
- Шрифт — Tiny5 (Google Fonts, OFL) в `--pixel` и `--body` (`style.css`); запасной — Handjet.
- `src/lighting.js` — живой свет (v0.62): WebGL-проход поверх 2D-сцены, источники — `sceneLights()` в `src/main.js`; нормали спрайтов — `assets/sprites/knight/n/`. **Свет v2 (v1.06):** `light.plus` — проход в буфер, яркое → размытие в 1/4 (свечение крупными пикселями), ступени по яркости (не по каналам — иначе цветные кольца), ореол и лучи от огней, блик на металле, холодные тени; тени героев на полу — `castShadow` в `src/main.js`. Переключатель «Свет: новый / прежний» — в паузе (`knightNight.lightPlus`).
- `src/palette.js` — цвета.
- `src/main.js` — цикл (фиксированный шаг 1/60 с), режимы title / play / dead / end, ввод (направления относительно взгляда рыцаря), объект `world` для врагов, стрелы, столкновения тел, эффекты, HUD.
- `index.html`, `style.css` — страница; HUD, надписи и окно диалога — DOM поверх canvas.
- `src/dialogue.js` — движок диалогов; `src/story/dialogues.js` — тексты (черновики) и `SHOPS` — реплики, товары и темы лавок; `docs/story.md` — сюжет владельца.
- `src/story/bestiary.js` — страницы журнала (бестиарий): как бьёт, как победить, описание врага.
- `src/tutorial.js` — шаги обучения у наставницы (чистая логика, есть тесты). `src/save.js` — сохранение в localStorage.
- `assets/portraits/` — портреты для диалогов (v0.63: **все перерисованы в PixelLab в одном стиле** — 64×64, увеличены до 256; Илиа и Лика — по описанию фото людей, с которых списаны, с их согласия; Найт — под потёртую броню №10; настроения Лики и усталый Найт — правкой портрета `edit-image-pixen`; варианты — `art/pixellab/portraits/sheets/`). Прежнее описание: **вырезанные без фона** (256×256 PNG с прозрачностью): `knight.png` — обычный, `knight-tired.png` — прищур (`mood: 'tired'`), `knight-nohelm.png` — без шлема (`mood: 'nohelm'`), `ilia.png`, `alkima.png` (наставница; сгенерирован в PixelLab по картинке владельца в стиле портрета Лики, волосы чёрные), `lika.png` и `lika-<настроение>.png` (happy, sly, surprised, sulky, serious, worried, angry; в лавке — `moods` в `SHOPS`, в диалогах — `mood` у реплики). Фон вырезается нейросетью: `pip install "rembg[cpu]"`, модель `birefnet-portrait` (лучше всего держит плюмаж и кольчугу), край — порог альфы 110. Подключаются в `FACES` в `src/main.js`.
- Стены из кусков PixelLab (v0.64): `tiles: 'dungeon' | 'castle'` (+ `tileCount`) у комнаты → `assets/backgrounds/<имя>/<имя>_<n>.png` (640×360, бесшовные, линия пола на куске — y 246); фон тогда строится в разрешении экрана (`c.k = 2` в `buildRoom`). Двери и убранство в таких комнатах — картинки `assets/objects/` (`OBJECTS`, `DECOR_IMG` в `src/background.js`). Инструменты: `tools/pixellab_room.py` (стены), `tools/pixellab_object.py` (предметы: варианты → `pick`).
- **Канон облика — `docs/art-canon.md` (владелец, 15.10):** на всех картинах герои одинаковы (капитан — маска, морион с красным плюмажем, белое сюрко с оранжевым солнцем; принцесса; замок с титульного экрана). Любая картинка — с эталоном (reference) и проверкой по списку перед вставкой.
- Фоны-картинки целиком (`image` у комнаты, `buildImageRoom`) не используются — решение владельца (v0.32: двери на картинках «летали»). Вместо них — куски стен (выше) и дальний план под открытым небом (`far` у комнаты, балкон, v0.67).
- `src/background.js` — фон комнат (стены, двери, решётки), факелы, портал, бочки, паутина, темнота.
- `src/title.js` — титульный экран: картина `assets/backgrounds/title.png` (v0.67) + живое поверх; без картинки — старый рисунок кодом.
- Карта замка — `MAP` в `src/config.js` (этаж, x, y, ширина в клетках), рисует `renderMap` в `src/main.js`; комнаты открываются флагами `map_<комната>`.
- Места отдыха — `rest` у пропа или убранства (диван, камин, скамья, костёр): сесть, лечение, сохранение; «продолжить» — с последнего (`flags.restAt`).
- Жизнь и щит — шкалы (v0.59): щит от брони (`shield` у предмета) принимает урон первым (`splitDamage` в `src/combat.js`), восстанавливается без попаданий. Сеты — `SETS` в `src/config.js` (сет мародёра: три свёртка `loot` по комнатам → броня, `speed` — множитель ходьбы).

Башня → дверь наверх → `mage` («Покои принцессы») — арена босса главы 1, призрака главы королевской стражи (v0.65: класс `Boss` в `src/enemy.js`, приёмы — `patterns` у `ENEMY_TYPES.boss`, удушение — `world.choke` и состояние рыцаря `held`); победа — конец главы (`finish` у встречи). Маг — позже.

- `tools/pixellab.py` — клиент PixelLab (генерация пиксель-арта); ключ — переменная окружения `PIXELLAB_API_KEY`, в репозиторий не класть. `generate-image-v2` с `style_image` (портрет-образец 64×64) и `reference_images` (картинка персонажа) держит стиль портретов; 16 вариантов 64×64 = 10 генераций. Пример — `tools/pixellab_alkima.py`.
- **Переходы по картинке (v1.0):** `paths` у комнаты — тропа / лестница / дверь, как нарисованы (`pts: [[x, y, масштаб]…]`, `keys`, `to`, `at: { path | door | edge }`); нарисованные двери — `kind: 'painted'` + `leaf` (створка из картины) + `mat` (коврик). Края комнат могут вести к тропе (`edges.left.at`). Покадровые враги — `ANIM_ENEMIES` в `src/main.js` (гоблины, анимации PixelLab `animate-character`: шаблон — 1 генерация, PixMiniMax 8 кадров — 1). **Дорого:** `animate-with-skeleton-v3` (≈25 за кадр) и холсты нестандартных размеров (72×48 ≈ 125) — сначала 2–4 пробы.
- **v1.02–1.03 (23.10):** `blend: true` у тропы — переход без затемнения (кадр наезжает и растворяется, `blendFrom`/`renderBlend`); `blocks` у комнаты и `block` у предмета — непроходимо (фонтан, клумбы); `push` у предмета — толкать руками (`shoveDx`, анимация рыцаря `push`; кухонный стол квеста служанки); окна лавок: `art.at` (где продавец), `art.fg` (стойка поверх), `art.still` (заплатки лица поверх картины — Шахбану нарисована в картину кофейни); `guide` у SHOPS — окно-справочник без товаров (библиотекарша Жанет, библиотека в ратуше `town_library`). **Окна лавок:** продавец либо нарисован в картину (inpaint), либо бюст в палитре сцены за стойкой — никогда не «наклейка» поверх.
- **v1.06 (24.10):** `zMin` у комнаты — ближе к стене не подойти (площадь: дома стоят на z≈8, иначе рыцарь «ходит по стене»; кто уже глубже — не выталкивается). `block` проверяет только середину рыцаря — нарисованным препятствиям давать полуширину с запасом ~5 на плечи; низким столам — блок на всю глубину столешницы. Сидящие горожане — картинка без стула, 48-холст (≈42 px), садятся к стулу стола-предмета. Швы кусков картины чинить inpaint с полосой, **залитой ровным цветом** (иначе модель копирует исходник), — `.pixellab_work/seam2/`.
- `src/decor.js` — убранство стен (`decor` у комнаты): окна, знамёна, портреты, гобелен, стойки, нары, кандалы, доспех, камин, люстра, плющ. `look` — разговор при осмотре (E).

Ветки: `main` — то, что видит тестер (GitHub Pages публикует `main`); `claude/parry-prototype` — старый бой в одной плоскости (v0.4); `claude/depth-prototype` — вариант A, слит в `main` в v0.8. Новые изменения — в ветке от `main`, затем PR в `main`.

## Решения владельца

- **Пропорции и единый пиксель (владелец, 22.10 — главное правило для всех картинок):** любой персонаж (NPC, камео, враг) — того же пиксельного характера и качества, что и рыцарь, и в его масштабе: взрослый ≈ рост рыцаря (рыцарь в игре ≈ 60 px с плюмажем), сидящий ≈ 44–46 px, ребёнок ниже. Не уменьшать готовые спрайты (теряют детали и выглядят грубее) — генерировать сразу в нужном размере (холст 64 — стоящий взрослый, 48 — сидящий/ребёнок) по образцу стиля рыцаря. Мебель и комнаты — в рост рыцаря; перед показом сравнить с рыцарем на скриншоте и с хорошими пиксельными играми (Undertale, Stardew Valley).

- Управление (после бета-теста): курсор выбирает высоту, ЛКМ — удар, держать ПКМ — защита, пробел — рывок, WASD — ходьба. Других схем нет.
- **Без автонаведения (владелец, 16.10, v0.93):** поворот — A / D или курсором (по другую сторону рыцаря); с защитой смотрит на курсор. Шрифт текста диалогов — Philosopher (Tiny5 — заголовки и интерфейс), переключается в паузе.
- Колесо — приём оружия (меч: вихрь, рапира: восьмёрка), перезарядка 4 с. Q — смена оружия.
- Начало: рыцарь отмечает порталы на карте; появляется в тёмной камере заброшенного замка, наставница учит драться (вместо чучела), торговка Лика — в отдельной лавке с меню как в Undertale. Тексты пишет владелец; всё в игре с пометкой [черновик].
- Второе оружие — рапира: её выбивают у Илиа последним ударом, он отступает. Набор приёмов — `RAPIER` в `src/config.js`, описание — `docs/design.md` (v0.12).

- **Канон главы 1 (владелец, 14.10) — не забывать в портретах, текстах и идеях:** замок **заброшен ≈ 200 лет**. Принцесса,
  служанки, стража — давно мертвы; живых жителей нет. В замке только: искатели приключений и мародёры, те, кто пришёл
  с особой целью (Алкима, Илиа, сам Найт), призрак главы стражи, монстры. Новых **призраков** добавлять можно (интересно).
  Живой кот Фуджин — исключение по решению владельца. Глава 1 — вступительная и короткая по числу локаций и сюжету
  (как Руины в Undertale), долгая только по первому знакомству с миром.
- **Смысл и дуга игры** — `docs/story.md` (путь и принятие, пятая личность, открытый финал, имя Найта — Азария, лицо — только пасхалка).
- **Свобода и границы (владелец, v0.73):** декоративные детали в комнатах (убранство, предметы, свет) добавлять без вопросов — владелец потом поправит. **Чётко утверждённую внешность не менять без вопроса** (лица/портреты, облик босса — белое сюрко и маска, Найт — первый портрет). Неутверждённое можно менять. Пожелание: чтобы у Найта были видны глаза — когда будет возможность сделать хорошо.
- **Режим работы (владелец, 14.10):** сюжет, мелкие детали и всё человеческое владелец делает сам. От Claude — черновики
  (дёшево, для вдохновения), оценка, архитектура и инженерия (как сделать, что возможно, что не стоит), советы по
  геймдизайну (как в играх избегают скуки, как разнообразить механики). Большие фронты — ночью или когда кредиты владельцу
  не нужны.
- **Бюджет:** «не жалея кредитов» действует на текущий фронт работ, пока владелец не скажет «экономь». Обычно — средний расход; владелец готов отдать до 70–80 % лимита. Он присылает замечания по ходу работы — это нормально, так он экономит время.
- **Расход PixelLab (владелец, 15.10):** тариф — 5000 генераций в месяц, обновляется в дату продления подписки (баланс — `GET /balance`).
  Перед прогоном больше ~200 генераций (перенос костюма на все кадры, десятки картин) — назвать владельцу оценку и ждать «да»;
  большой прогон начинать с 2–4 пробных кадров и проверять их; варианты заказывать по 4–8, а не по 16–25.
- **Графика (v0.58, решение владельца):** делаем в PixelLab (`tools/pixellab.py`, заготовки — `art/`). Экран расширяем до **640×360** (целое масштабирование: ×3 = 1920×1080, потом полноэкранный режим), персонажи ≈ 64 px. Раньше было 320×180 и 32×32 — отменено.
- Найт — стройный, изящный, средне-высокого роста (не коренастый), основа — вариант №10 (`art/pixellab/knight-clean/kn2_09.png`). Стартует в **потёртой** броне и со старым мечом; броню и оружие можно менять (броня — «состояния» персонажа PixelLab с теми же позами скелета, оружие рисуется отдельно кодом по углу клинка).
- Свет — шейдером (WebGL, карты нормалей), не фильтрами. Выбор владельца: живой свет, **свет ступенями** (пиксельные кольца, не плавно), **пыль в воздухе**, настроение **«Тёплое»**. Фонаря у рыцаря нет (может стать предметом позже). Демо — `art/light-demo/`. Фоны заказывать равномерно освещёнными.
- Спрайты — PNG-листы, чтобы владелец мог править их в Piskel / Aseprite.

## Процесс

- Работа в ветке → PR в `main`. Репозиторий публичный.
- **Решение владельца:** то, о чём договорились (его просьбы и исправления), — сливать в `main` сразу после проверки, не спрашивая: он тестирует по ссылке, лишние вопросы тратят его лимит.
- Свежая версия по ссылке без Ctrl+F5 — `sw.js` (сервис-воркер проверяет файлы на сервере при каждом заходе).
- После изменений: `npm test` и прогон в браузере (без ошибок в консоли).
